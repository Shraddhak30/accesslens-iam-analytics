# AccessLens: IAM Access Review & Risk Analytics

An end-to-end identity and access management (IAM) analytics project. It reconciles HR, Active Directory and application entitlement data in SQL, finds access risks and data-quality defects, and reports on them in a Power BI dashboard built for access-review owners and leadership.

> **Status: in progress.** The data generator is complete. SQL reconciliation views and the Power BI dashboard are being built. See [Roadmap](#roadmap).

> **All data in this repository is synthetic.** It was generated by the script in `data_generator/` and contains no real employee, employer or client information.

---

## Why this project

Quarterly access reviews and joiner/mover/leaver controls depend on one question: *does everyone have exactly the access they should, and can we prove it?* In practice, the answer lives across several systems that rarely agree with each other. AccessLens reproduces that problem on realistic data and shows how to:

- reconcile identity sources to surface orphaned, excess and dormant access
- detect separation-of-duties (SoD) conflicts
- track certification campaigns and SLA performance
- turn the results into clear, defined metrics for governance reporting

## Dataset

The generator produces seven tables (about 11,000 rows in total) that model a mid-sized organisation:

| Table | Rows | Description |
|---|---:|---|
| `hr_employees` | 1,000 | Authoritative HR feed: department, manager, status, termination date |
| `ad_accounts` | 1,031 | Directory accounts: linked employee, enabled flag, last logon, privileged flag |
| `applications` | 15 | Business applications with owner and criticality |
| `entitlements` | 2,656 | Application roles granted to each account |
| `sod_rules` | 5 | Role pairs that must never be held by one person |
| `certifications` | 4,187 | Review items across Q1–Q3 2026 campaigns, with reviewer and decision |
| `access_tickets` | 2,500 | Provision, modify, deprovision and password-reset requests with SLA targets |

### Planted risks and defects

The generator deliberately seeds problems that real IAM teams look for, and writes an `answer_key.csv` listing every one. This makes the SQL logic testable: each query's output can be checked against a known correct result.

| Issue | Count | Type |
|---|---:|---|
| Terminated users with enabled accounts | 33 | Access risk |
| Orphaned accounts (no HR record) | 25 | Access risk |
| SoD conflicts | 18 | Access risk |
| Dormant enabled accounts (90+ days) | 103 | Access risk |
| Overdue certification items | 96 | Process / compliance |
| Ticket SLA breaches | 241 | Process / compliance |
| Duplicate accounts for one employee | 6 | Data quality |
| Grant dates in the future | 5 | Data quality |
| Decisions dated before campaign start | 4 | Data quality |
| Applications with no owner | 2 | Data quality |

The dataset is reproducible: a fixed random seed means every run produces identical data, and the reference date ("today") is fixed at **29 October 2026**.

## Getting started

**1. Generate the data**

```bash
pip install pandas faker
python data_generator/generate_iam_data.py --out data
```

**2. Load into SQL Server**

Create a database (for example `AccessLens`), then load each CSV with SSMS → *Tasks* → *Import Flat File*, or run `sql/01_create_tables.sql`.

**3. Build the reconciliation views**

Run `sql/02_reconciliation_views.sql` and `sql/03_data_quality_checks.sql`. Use the fixed reference date `'2026-10-29'` rather than `GETDATE()` so results match the answer key.

**4. Open the dashboard**

Open `powerbi/AccessLens.pbix` and point the data source at your SQL Server instance.

## Dashboard pages

1. **Executive summary:** headline KPIs and trends for leadership.
2. **Reconciliation exceptions:** drill-down lists of every flagged account and entitlement.
3. **Certification tracker:** campaign progress by reviewer, application and decision.
4. **SLA performance:** request volumes and breach rates by request type.

## Metric definitions

| Metric | Definition |
|---|---|
| Certification Completion % | Items with a decision (Approved or Revoked) ÷ total items in the campaign |
| Revocation Rate % | Items Revoked ÷ items with a decision |
| Overdue Items | Items still Pending after the campaign due date |
| Orphaned Accounts | Accounts whose `emp_id` has no match in `hr_employees` |
| Leaver Access Exceptions | Enabled accounts belonging to employees with status Terminated |
| Dormant Accounts | Enabled accounts with no logon in the 90 days before the reference date |
| SoD Conflicts | Accounts holding both roles of any pair in `sod_rules` |
| SLA Breach % | Closed tickets whose resolution time exceeded the SLA for their type ÷ all closed tickets |

Full column-level definitions are in [`docs/data_dictionary.md`](docs/data_dictionary.md).
